# Единый инженерный стандарт v1

Источник: Repo Factory / policy/engineering-quality.

1. Перед изменением зафиксировать наблюдаемый результат и критерий приёмки.
2. Воспроизвести проблему или проверить требование в изолированном тесте.
3. После двух неудачных исправлений с общей гипотезой проверить исходную предпосылку и пересмотреть архитектуру.
4. Исправить причину, затем выполнить регрессионные проверки; не заменять тест поведения проверкой текста реализации.
5. Соблюдать границы полномочий, не вмешиваться в активную пользовательскую сессию и не заменять установленные приложения без отдельной проверки.
6. Использовать локальные проверки с отчётом по SHA коммита; не запускать GitHub Actions без действующего разрешения.
7. Разделять: сборка, изолированные тесты, реальная интеграция, установленное приложение, приёмка владельца.
8. Не считать пустую конфигурацию проверок успешно протестированным проектом.
9. Не изменять чужие незакоммиченные файлы, указывать точные пути и использовать атомарные коммиты.
10. Перед выпуском проверять сохранение состояния, установщик и возможность отката.

Запуск после настройки quality/standard.json:

```powershell
python scripts/quality_runner.py --plan
python scripts/quality_runner.py --profile quick
python scripts/quality_runner.py --profile full
```

Команды задаются JSON-массивами без shell-интерполяции. Допустимы только
`python`, `dotnet`, `node`; вид проверки — unit/build/mock/sandbox/static.
Обязательны: id, kind, command, timeout_sec. Шаблон без проверок выводит
`NOT_CONFIGURED` и код ошибки, а не PASS. Отчёты сохраняются локально в
`quality/reports/`, исключённом из Git. Автоматический контроль качества
не доказывает работоспособность реального ChatGPT и не разрешает релиз.
